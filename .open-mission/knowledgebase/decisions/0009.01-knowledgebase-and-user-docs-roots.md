## Context

The previous `.open-mission/documentation/` tree mixed agent-facing governance, generated Entity pages, architecture authority, user manual pages, essays, and course material. It also had two Entity folders:

- `architecture/entities/`
- `entities/`

That made agent discovery ambiguous. Agents had to infer which page was canonical, and user-facing docs inherited internal governance language.

## Decision

Open Mission uses two documentation roots:

| Root | Audience | Authority |
| --- | --- | --- |
| `.open-mission/knowledgebase/` | agents and maintainers | canonical product, Entity, architecture, decision, contract, doctrine, operations, and quality authority |
| `.open-mission/docs/` | operators and contributors | user-facing tutorials, how-to guides, concepts, reference, and explanations |

Entity documentation has one canonical folder:

```text
.open-mission/knowledgebase/entities/
```

Entity pages define what the Entity is, what it owns, its state, commands, relations, runtime behavior, source files, and governing decisions. Generated implementation details may appear inside the Entity page or as explicitly marked implementation-surface sections, but they must not create a second Entity documentation root.

User docs follow a Diataxis-style shape:

- `tutorials/` for learning workflows
- `guides/` for task-oriented how-to material
- `concepts/` for user-facing explanations of product concepts
- `reference/` for exact lookup material
- `explanations/` for background essays

## Consequences

- StorageRoot source provisioning seeds `.open-mission/knowledgebase/` and `.open-mission/docs/` instead of `.open-mission/documentation/`.
- The web `/docs` route reads `.open-mission/docs/`.
- Governance-writer skills write Entity pages under `.open-mission/knowledgebase/entities/`.
- Existing ADR numbers remain stable registry keys. Superseded ADRs remain historical records and must not be counted as active authority without checking `status` and supersession notes.
- New decisions should be added only when they define durable authority. Routine documentation moves should update this decision or the affected index page rather than creating another ADR.
